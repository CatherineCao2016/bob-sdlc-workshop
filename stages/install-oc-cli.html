Setup · oc CLI
Install the oc CLI
Get the OpenShift command-line tool on macOS, Windows, or Linux. It's the only local tool the deploy lab needs.
💬 What you're installing
  • oc is the OpenShift CLI. It's a single self-contained binary that behaves identically on macOS, Windows, and Linux, so the commands in the lab work the same everywhere.
  • You do not need Docker, Podman, or Java on your laptop for this workshop. Images are built on the cluster, not on your machine, so oc is all you have to install locally.
  • Pick the section for your operating system below, or jump to the web console download, which is the most reliable path because it always matches your cluster's version.
Install by Operating System
1
macOS
The simplest path is Homebrew. It installs the right build for your machine automatically, so Apple Silicon (M-series) and Intel Macs both just work with the same command. 
brew install openshift-cli

# confirm it's on your PATH
oc version --client
Without Homebrew. Download the macOS archive from the OpenShift mirror, unpack it, and move oc onto your PATH. 
# Apple Silicon: use the -arm64 archive. Intel: use the plain mac archive.
curl -LO https://mirror.openshift.com/pub/openshift-v4/clients/ocp/stable/openshift-client-mac-arm64.tar.gz
tar xzf openshift-client-mac-arm64.tar.gz
sudo mv oc kubectl /usr/local/bin/
oc version --client
📝 Note
On a Mac, the first time you run a downloaded binary you may need to approve it under System Settings > Privacy & Security. Homebrew installs avoid this prompt.
2
Windows
Download the Windows zip from the mirror, extract it, and add the folder that contains oc.exe to your PATH. Once it's on the PATH, oc works in both PowerShell and Command Prompt. 
# 1. Download this file in a browser:
#    https://mirror.openshift.com/pub/openshift-v4/clients/ocp/stable/openshift-client-windows.zip
# 2. Extract it, e.g. to C:\oc
# 3. Add C:\oc to your PATH:
#    Start menu -> "Edit the system environment variables"
#    -> Environment Variables -> select "Path" -> Edit -> New -> C:\oc -> OK
# 4. Open a NEW terminal so the PATH change takes effect, then:
oc version --client
With a package manager. If you already use Scoop or Chocolatey, you can let it handle the download and PATH for you. 
# Scoop
scoop install openshift-cli

# Chocolatey (run in an elevated prompt)
choco install openshift-cli
3
Linux
Download the Linux tarball from the mirror, unpack it, and move oc into a directory on your PATH such as /usr/local/bin. 
curl -LO https://mirror.openshift.com/pub/openshift-v4/clients/ocp/stable/openshift-client-linux.tar.gz
tar xvf openshift-client-linux.tar.gz
sudo mv oc kubectl /usr/local/bin/
oc version --client
📝 Note
On ARM-based Linux, use the openshift-client-linux-arm64.tar.gz archive from the same mirror directory instead.
Easiest cross-OS path: the web console
4
Download oc from the OpenShift web console
Every OpenShift web console offers the matching oc download for all operating systems, so you don't have to guess a version. Open the console in a browser, then:
  1. Click the ? (Help) icon in the top-right toolbar.
  2. Choose Command line tools.
  3. Download the oc build for your operating system, then unpack it and put it on your PATH exactly as in the sections above.
💡 Tip
The console's Command line tools download always matches your cluster's version, which avoids the occasional client/server version warning you can get from a generic stable download. When in doubt, use this path.
Verify and Log In
5
Verify the install
Confirm oc is on your PATH and runnable. The --client flag prints only the client version, so it works before you've logged in to anything. 
oc version --client

# Once you're logged in, plain `oc version` also shows the server version,
# which is handy for spotting a client/server version mismatch.
oc version
6
Log in to the cluster
Log in with a token and the cluster's API URL. You get both from your instructor, or from the web console: click your name in the top-right, choose Copy login command, and it gives you the full oc login line with a fresh token. 
oc login --token=<your-token> --server=<cluster_url>

# confirm you're connected and see your current project
oc whoami
oc project
📝 Note
Tokens are short-lived. If oc later reports that you're not logged in, grab a fresh Copy login command from the console and run it again.
